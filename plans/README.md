## Decisions taken

- **PR target**: a new branch into `secoro` (the fork's integration branch).
  `master` stays a clean upstream mirror, which is what keeps the later
  cherry-picks onto upstream trivial.
- **Round 1 is KDL only.** `motion-spec` is not touched this round.
- **SVD truncation threshold is left alone.** The fork's `1e-8` (upstream is
  `1e-14`) stays as-is. Not revisited by any plan here.
- **Measured vs. virtual wrench distinction is deferred.** Plan 004 hard-codes
  all-ones weights (classic behaviour) rather than guessing per model.

## Two rounds, and why the split is forced

Round 1 contains only changes that are **additive and behaviour-preserving**,
so `motion-spec` keeps compiling and every existing model behaves identically.

Round 2 contains the two changes that are **downstream-breaking**, and they
must merge in lockstep with the `motion-spec` template PR:

- Plan 001 removes `E_input`, which silently redefines what `beta` means for
  every generated controller.
- Plan 004 deletes the forked solver classes, which
  `motion-spec/src/motion_spec/templates/domain_solver.stg` still references by
  name.

Neither can ship without the corresponding template change, which is why they
are not in round 1.

## Key findings behind these plans

All verified by direct measurement, not inference. The two probe programs are
in `plans/reference/` and are runnable — see the build lines in their header
comments.

1. **The `_fext` solver does not compute the external-wrench contribution.**
   With a zero external wrench it returns `(10.46, -20.14, 11.84)` Nm — pure
   gravity, because both solver instances get the same non-zero `root_acc`.
   With gravity removed it still returns `(0.67, -1.62, 1.30)` Nm at
   1–2 rad/s, because `child.PC` still leaks into `s.R_tilde`. The downstream
   `KDL::Add()` of the two passes therefore double-counts gravity and bias.
   (`plans/reference/achd_probe.cpp`)

2. **The fork's `E_input` term is a change of input convention, not a fix.**
   It is exactly equivalent to the caller passing `beta + alpha^T * root_acc`:
   max deviation `1.4e-14` in `tau` and `q_dotdot` over a 12-pose sweep with
   non-zero velocity, feed-forward torque and external wrench. It also breaks
   the `beta == getTransformedLinkAcceleration()` correspondence that upstream's
   own test asserts. (`plans/reference/achd_beta_semantics.cpp`)

3. **Upstream's fixed-joint support is incomplete.** Four `!= Joint::Fixed`
   guards exist but they only guard the joint-index counter. Three divisions by
   `D` (which is 0 for a fixed joint) are unguarded and produce `NaN` that
   propagates through the whole solve, returning `E_NOERROR`. There is also a
   latent out-of-bounds `q(j)` read at `chainhdsolver_vereshchagin.cpp:93`.

4. **The weighting mechanism is small because the recursion is already
   factored for it.** `P_tilde`, `D`, `Z`, `E`, `M` do not depend on any force
   input; only `R`, `u`, `G` do, and affinely. So a per-driver contribution
   rides the same recursion in a parallel accumulator and sums back to today's
   totals exactly. The weight then applies at exactly one line, in
   `constraint_calculation()`.

## Findings considered and rejected

- **Reverting the SVD truncation threshold to upstream's `1e-14`.** Explicitly
  left alone by decision. The fork's `1e-8` stays.
- **Making `getTransformedLinkAcceleration()` return the true acceleration.**
  It is consistent with `beta` today; changing one without the other
  desynchronises them, and changing both is a breaking change to a stable
  release line for no functional gain. Documented instead (plan 001).
- **Adding a fifth solver class for the weighted variant.** This is the habit
  that produced the four forked files. The weighting is ~40 lines inside the
  existing class with a default-off switch.
- **Adding weights as a `CartToJnt` parameter.** Breaks every caller and the
  PyKDL binding for a value that changes far less often than the per-tick
  inputs. A setter is correct.
- **Porting the fork's `Joint::setInertia` / `Segment::getMutableJoint`
  upstream.** No non-generated consumer found. Plan 004 confirms and drops them.
